Questão 1(b) e 1(c): limites restritos e como melhorar o algoritmo

O item (b) usa as notações das Aulas 3 e 4 sobre os $T(n)$ do item (a). O item (c) pede para pensar como projetista: trocar a força bruta por uma ideia que já vimos (ordenação ou contagem).

Lembrete do item (a)

$T_m(n) = 9$ (melhor caso) e $T_p(n) = 3n^2 - n - 1$ (pior caso).

Questão 1(b) (1,5 pts)

Enunciado

Especifique um limite assintoticamente restrito para o algoritmo tanto no pior quanto no melhor caso e prove que tais limites estão corretos. Utilize um dos métodos de prova ensinados em sala (usando limites ou encontrando os valores de $c$ e $n_0$). Lembre-se de desenvolver a prova e explicar o que foi feito.

Leia com atenção

"Limite assintoticamente restrito" é o nome da notação $\Theta$ (Aula 4). Responder só com $O$ ou só com $\Omega$ perde ponto. E o enunciado pede prova com explicação, não só a resposta.

Resposta

Melhor caso: $\Theta(1)$ · Pior caso: $\Theta(n^2)$

Prova do melhor caso: $9 = \Theta(1)$

Aqui $f(n) = 9$ e $g(n) = 1$. Pela definição, precisamos de constantes positivas $c_1$, $c_2$ e $n_0$ com $c_1\cdot 1 \le 9 \le c_2 \cdot 1$ para todo $n \ge n_0$.

Tome $c_1 = c_2 = 9$ e $n_0 = 2$. Para todo $n \ge 2$: $9 \cdot 1 \le 9 \le 9 \cdot 1$, que é verdade. Logo $T_m(n) = \Theta(1)$. ∎

Ou pelo limite: $\lim_{n\to\infty} \frac{9}{1} = 9$, uma constante finita e positiva. Então as funções têm a mesma taxa de crescimento: $\Theta(1)$.

$n_0 = 2$ porque o algoritmo só faz sentido como analisamos com pelo menos 2 elementos (o melhor caso pressupõe $\text{vetor}[0]$ e $\text{vetor}[1]$).

Prova do pior caso: $3n^2 - n - 1 = \Theta(n^2)$, pela definição

Precisamos de $c_1, c_2, n_0 > 0$ com $c_1 n^2 \le 3n^2 - n - 1 \le c_2 n^2$ para todo $n \ge n_0$. Vamos provar cada lado separadamente (teorema: $\Theta \iff O$ e $\Omega$).

Lado de cima ($O$): para $n \ge 1$, os termos $-n$ e $-1$ são negativos, então $$3n^2 - n - 1 \le 3n^2.$$ Logo vale com $c_2 = 3$ e $n_0 = 1$.

Lado de baixo ($\Omega$): escolha $c_1 = 2$, um pouco menor que o coeficiente líder 3, e resolva: $$3n^2 - n - 1 \ge 2n^2 \iff n^2 - n - 1 \ge 0.$$ As raízes de $n^2 - n - 1$ são $\frac{1 \pm \sqrt5}{2}$, ou seja, $\approx -0{,}62$ e $\approx 1{,}62$. A parábola é $\ge 0$ para $n \ge 1{,}62$, ou seja, para todo inteiro $n \ge 2$. Logo vale com $c_1 = 2$ e $n_0 = 2$.

Juntando: com $c_1 = 2$, $c_2 = 3$ e $n_0 = \max(1, 2) = 2$: $$2n^2 \le 3n^2 - n - 1 \le 3n^2 \quad \text{para todo } n \ge 2.$$ Confira em $n = 2$: $8 \le 9 \le 12$ ✓. Portanto $T_p(n) = \Theta(n^2)$. ∎

O sanduíche: $2n^2 \le 3n^2 - n - 1 \le 3n^2$

A mesma prova pelo limite (alternativa)

$$\lim_{n\to\infty}\frac{3n^2 - n - 1}{n^2} = \lim_{n\to\infty}\left(3 - \frac{1}{n} - \frac{1}{n^2}\right) = 3.$$

O limite é uma constante finita e positiva, então $T_p(n)$ e $n^2$ têm a mesma taxa de crescimento: $T_p(n) = O(n^2)$ e $T_p(n) = \Omega(n^2)$, logo $T_p(n) = \Theta(n^2)$.

Qual método usar na prova?

O enunciado aceita qualquer um. O do limite é mais curto, mas escreva a interpretação ("constante finita e positiva → mesma taxa → $\Theta$"). O de $c$ e $n_0$ exige mostrar a conta de cada lado e conferir um valor. Fazer os dois não rende ponto extra; faça um bem feito.

Modelo de resposta (1b)

Melhor caso: $T_m(n) = 9 = \Theta(1)$. Tomando $c_1 = c_2 = 9$ e $n_0 = 2$, temos $9\cdot 1 \le 9 \le 9\cdot 1$ para todo $n \ge n_0$.

Pior caso: $T_p(n) = 3n^2 - n - 1 = \Theta(n^2)$. Superior: para $n \ge 1$, $3n^2 - n - 1 \le 3n^2$ ($c_2 = 3$). Inferior: $3n^2 - n - 1 \ge 2n^2 \iff n^2 - n - 1 \ge 0$, verdadeiro para $n \ge 2$ ($c_1 = 2$). Logo $2n^2 \le T_p(n) \le 3n^2$ para todo $n \ge n_0 = 2$.

Questão 1(c) (1,5 pts)

Enunciado

É possível modificar o algoritmo de forma que a complexidade assintótica do pior caso seja reduzida. Explique como isso pode ser feito e especifique qual seria a complexidade resultante para o pior caso após tais modificações.

Onde está o desperdício? O algoritmo compara cada elemento com todos os outros: $\frac{n(n-1)}{2}$ comparações. Mas, se o vetor estiver ordenado, elementos iguais ficam vizinhos, e basta comparar cada um com o seguinte: $n - 1$ comparações.

Solução esperada: ordenar e varrer

VerificaTodosUnicos2(vetor, n)
1   MergeSort(vetor, 0, n − 1)          // ou HeapSort: O(n log n) no pior caso
2   para i ← 0 até n − 2 faça          // O(n)
3      se vetor[i] == vetor[i + 1] então
4         retorna False
5   retorna True
  • Ordenar com MergeSort (Aula 7) ou HeapSort (Aula 9) custa $O(n\log n)$ no pior caso.
  • A varredura comparando vizinhos custa $O(n)$.
  • Total: $O(n\log n) + O(n) = O(n\log n)$.

Pior caso depois da modificação: $\Theta(n\log n)$, contra $\Theta(n^2)$ antes

Armadilha

Não use QuickSort nem InsertionSort como justificativa para o pior caso. O pior caso do QuickSort é $\Theta(n^2)$ (Aula 7), e o do Insertion também (Aula 2). A melhoria só vale com um algoritmo que seja $O(n\log n)$ no pior caso: MergeSort ou HeapSort.

Alternativa: usar que são inteiros não-negativos (ideia do CountingSort)

O enunciado diz que os elementos são inteiros não-negativos. Se o maior valor for $k$, dá para usar um vetor de contagem como o $C[0..k]$ do CountingSort (Aula 8):

VerificaTodosUnicos3(vetor, n, k)
1   para v ← 0 até k faça visto[v] ← False        // O(k)
2   para i ← 0 até n − 1 faça                     // O(n)
3      se visto[vetor[i]] então retorna False
4      visto[vetor[i]] ← True
5   retorna True

Custo: $O(n + k)$, que é $O(n)$ quando $k = O(n)$. Como no CountingSort, só compensa se $k$ não for enorme perto de $n$. Citar essa alternativa, com essa ressalva, mostra domínio do conteúdo.

Comparações no pior caso: original × ordenar e varrer

Laranja: $\frac{n(n-1)}{2}$ comparações do algoritmo original. Azul: cerca de $n\log_2 n$ (MergeSort) $+ (n-1)$ (varredura). Com $n = 1000$: cerca de 500 mil contra cerca de 11 mil.

Para ir além (fora da matéria)

Dá para provar que qualquer algoritmo baseado em comparações para esse problema precisa de $\Omega(n\log n)$ comparações no pior caso, com um argumento parecido com a árvore de decisão da Aula 8. Então "ordenar e varrer" é o melhor possível nesse modelo. Só fugindo das comparações (contagem, ou tabela hash, que dá tempo esperado linear) se faz melhor.

Modelo de resposta (1c)

Sim. Primeiro ordena-se o vetor com um algoritmo $O(n\log n)$ no pior caso, como MergeSort ou HeapSort. Num vetor ordenado, elementos repetidos ficam em posições consecutivas, então basta uma única varredura comparando $\text{vetor}[i]$ com $\text{vetor}[i+1]$, em $O(n)$. A complexidade de pior caso passa a ser $O(n\log n) + O(n) = \Theta(n\log n)$, menor que o $\Theta(n^2)$ original.
