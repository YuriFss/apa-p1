Aula 8: Ordenação em tempo linear

Limite inferior por comparações

  • Algoritmo por comparação = árvore de decisão binária. Pior caso = altura $h$.
  • Folhas $\ge n!$ (todas as permutações); árvore de altura $h$ tem $\le 2^h$ folhas.
  • $2^h \ge n! \Rightarrow h \ge \log n! \ge c\,n\log n$. Logo, $\Omega(n\log n)$ comparações no pior caso.
  • Não vale para quem não compara: CountingSort, RadixSort, BucketSort.

CountingSort

Entrada: $n$ inteiros em $[0, k]$. Vetores: $A[0..n-1]$ entrada, $B[0..n-1]$ saída, $C[0..k]$ contagem.

CountingSort(A, B, k, n)
1.   for i ← 0 to k do C[i] ← 0                     // O(k)
4.   for j ← 0 to n − 1 do C[A[j]] ← C[A[j]] + 1     // O(n)  contar
7.   for i ← 1 to k do C[i] ← C[i] + C[i − 1]       // O(k)  acumular
10.  for j ← n − 1 downto 0 do                      // O(n)  posicionar
11.     B[C[A[j]] − 1] ← A[j]
12.     C[A[j]] ← C[A[j]] − 1
  • Ideia: "há $m$ elementos menores que $x$" $\Rightarrow$ $x$ vai na posição $m + 1$.
  • Exemplo: $A = [2,5,3,0,2,3,0,3]$, $k = 5$: contagem $C = [2,0,2,3,0,1]$; acumulado $C = [2,2,4,7,7,8]$; $B = [0,0,2,2,3,3,3,5]$.
  • Tempo $O(n + k)$, pseudolinear. Com $k = O(n)$: $O(n)$.
  • Estável, graças ao downto. MergeSort e InsertionSort também são estáveis.
  • Slide 15 diz "$k = 10$" para valores em $[0,9]$ (contando os valores); no pseudocódigo, $k$ é o maior valor.
