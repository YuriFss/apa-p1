1. Paradigmas de projeto de algoritmos

Paradigmas são técnicas genéricas para construir algoritmos. Eles fornecem uma abstração do algoritmo usado para resolver um problema. Exemplos: divisão e conquista, algoritmos gulosos, programação dinâmica etc.

2. Divisão e conquista: as três etapas

É uma técnica que consiste em dividir um problema maior e mais complexo em subproblemas menores e, depois, combinar as soluções dos subproblemas para gerar a solução do problema original. Geralmente cada subproblema tem só uma fração do tamanho do original, o que pode reduzir bastante o tamanho dos subproblemas.

Três etapas (slide 4), resolvidas recursivamente
  1. Divisão: dividir o problema em subproblemas que são instâncias menores do mesmo problema.
  2. Conquista: resolver os subproblemas recursivamente. Se o subproblema for suficientemente pequeno, resolve-se de forma direta (é o caso base).
  3. Combinação: combinar as soluções fornecidas pela conquista até resolver o problema original.

3. A recorrência típica: $aT(n/b) + f(n)$

Algoritmos de divisão e conquista costumam ter recorrências com um formato típico:

$$T(n) = \textcolor{#2a78d6}{a}\; T\!\left(\frac{n}{\textcolor{#d03b3b}{b}}\right) + \textcolor{#1baf7a}{f(n)}$$
SímboloSignificadoPergunta para achar
$a$número de subproblemas criadosquantas chamadas recursivas a função faz?
$b$tamanho de cada subproblema em relação ao original ($n/b$)em quantas partes o problema foi dividido?
$f(n)$custo da divisão e da combinaçãoquanto trabalho a chamada faz fora das chamadas recursivas?

Compare com a Aula 5: lá os subproblemas eram $n - 1$ (subtrair). Aqui são $n/b$ (dividir), e é isso que torna a divisão e conquista tão eficiente.

4. Busca binária: ideia e pseudocódigo

Problema: encontrar um elemento em um vetor ordenado.

Ideia básica: supondo o vetor já ordenado, olhe o elemento do meio. Se ele for menor que o procurado, o procurado só pode estar na metade da direita. Se for maior, só pode estar na metade da esquerda. Repita o processo na metade certa até encontrar o elemento.

Exemplo do slide, procurando 10 em $[3, 4, 5, 6, 7, 8, 9, 10]$, com $meio = \lfloor n/2 \rfloor$:

binarySearch(A, E, L, R)
1.  if R < L:
2.     return −1
3.  m ← floor((L + R) / 2)
5.  if A[m] < E:
6.     return binarySearch(A, E, m+1, R)
7.  else if A[m] > E:
8.     return binarySearch(A, E, L, m−1)
9.  else:                      // caso A[m] == E
10.    return m

A numeração pula a linha 4, como no slide. Chamada inicial: binarySearch(A, E, 0, n−1). L e R delimitam o trecho onde E ainda pode estar.

5. Animação

binarySearch em A = [3, 4, 5, 6, 7, 8, 9, 10]

Cinza: fora de $[L, R]$, já descartado. Laranja: $A[m]$, o elemento do meio. Verde: encontrado.

6. Melhor e pior caso

  • Melhor caso: o valor buscado está na posição $m$, no meio do vetor. Nenhuma chamada recursiva é feita: $\Theta(1)$.
  • Pior caso: o elemento não está no vetor, ou está presente mas só é encontrado quando o algoritmo chega ao caso base, numa partição com 1 elemento. Exemplo: o próprio 10 do slide.

7. A recorrência da busca binária

A árvore de recursão para encontrar o 10 é uma corrente: cada chamada faz trabalho constante (custo $c$: comparar e calcular o meio) e no máximo uma chamada, com metade do tamanho.

  • $a = 1$: uma única chamada recursiva (linha 6 ou linha 8, nunca as duas);
  • $b = 2$: o subproblema tem metade do tamanho;
  • $f(n) = \Theta(1)$: só comparações e o cálculo de $m$.
$$T(n) = \begin{cases} 1 & n = 1 \\ T\!\left(\dfrac{n}{2}\right) + \Theta(1) & n > 1 \end{cases}$$

8. Resolvendo: $\Theta(\log n)$

Complemento: os slides param na recorrência. A resolução usa o método iterativo da Aula 5.

Troque $\Theta(1)$ por uma constante $c$ e suponha que $n$ é potência de 2, $n = 2^m$, para as divisões serem exatas.

$$\begin{aligned} T(n) &= T(n/2) + c && \text{passo 1}\\ &= \big(T(n/4) + c\big) + c = T(n/2^2) + 2c && \text{passo 2}\\ &= T(n/2^3) + 3c && \text{passo 3}\\ &= T(n/2^k) + k\,c && \text{passo } k \end{aligned}$$

Caso base: $\dfrac{n}{2^k} = 1 \iff 2^k = n \iff k = \log_2 n$.

$$T(n) = T(1) + c\log_2 n = 1 + c\log_2 n.$$

$T(n) = \Theta(\log n)$

Intuição

"Quantas vezes dá para dividir $n$ por 2 até chegar em 1?" A resposta é $\log_2 n$. Com $n = 1\,000\,000$ são cerca de 20 chamadas, contra até 1 milhão de comparações da busca sequencial.

Novidade em relação à Aula 5

Quando o argumento divide ($n/2$), o caso base dá uma equação com potência, $n/2^k = 1$, e $k$ sai como um logaritmo. Quando o argumento subtrai ($n-1$), $k$ sai linear ($k = n$ ou $n - 1$).
