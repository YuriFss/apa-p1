Melhor caso, pior caso e caso médio

Quando o número de execuções de uma linha depende dos valores da entrada, e não só do tamanho $n$, não existe um único $T(n)$. Esta lição cobre os slides 18 a 30 da Aula 1 (ArrayMax e busca sequencial) e é a base das questões 2, 7 e 8 da lista.

1. O problema: linhas que dependem dos dados

O professor pergunta: "O que fazer em um caso assim?"

ArrayMax(A, n)
1.  currentMax = A[0]
2.  for i = 1 to n − 1:
3.     if A[i] > currentMax:
4.        currentMax = A[i]
5.
6.  return currentMax

As linhas 1, 2, 3 e 6 têm # exec fixo: 1, $n-1$, $n-1$ e 1. Mas a linha 4 só roda quando o teste da linha 3 dá verdadeiro, e isso depende dos valores em $A$, não só de $n$:

  • $A = [9, 1, 2, 3]$: o primeiro já é o maior, e a linha 4 roda 0 vezes.
  • $A = [1, 2, 3, 9]$: cada elemento é um novo máximo, e a linha 4 roda 3 vezes.
Ideia central (slide 21)

O tempo de execução pode ser influenciado pela organização dos dados de entrada, e não apenas pelo tamanho da entrada.

2. Os três cenários

É inviável analisar cada configuração de entrada possível. Por isso, na análise assintótica, consideramos 3 cenários:

CenárioO que é
Melhor casoCaso otimista: a entrada está organizada da melhor forma possível e o algoritmo executa a menor quantidade possível de passos.
Pior casoCaso pessimista: a entrada está organizada da pior forma possível para o algoritmo e ele executa a maior quantidade possível de passos.
Caso médioMédia dos tempos de execução sobre as entradas possíveis. Frequentemente difícil de determinar.
Erro clássico

O melhor caso não é "n pequeno". O tamanho $n$ é fixo e arbitrário. O melhor caso é a arrumação dos $n$ valores que faz o algoritmo trabalhar menos. Por isso a resposta sempre descreve a entrada ("o primeiro elemento é o maior", "vetor em ordem crescente") e o $T(n)$ continua sendo função de $n$.

"Pior forma para o algoritmo" também importa: um vetor ordenado é o melhor caso para um algoritmo e pode ser o pior para outro.

Usamos o pior caso com mais frequência porque:

  • ele impõe um limite superior para o número de passos sob qualquer entrada. Nenhuma entrada de tamanho $n$ gasta mais que isso;
  • geralmente é mais simples de avaliar que o caso médio.

Pior caso: $T(n) = 6n - 3$

Por que "elementos únicos"?

O teste é A[i] > currentMax, com $>$ estrito. Em $[1, 3, 3, 5]$, o segundo 3 não é maior que o 3 atual, e a linha 4 roda só 2 vezes. Para a linha 4 rodar em toda iteração, cada elemento precisa ser estritamente maior que todos os anteriores: valores distintos em ordem crescente. Esse tipo de detalhe vale ponto na justificativa.

Qualquer outra entrada fica entre os dois: $4n - 1 \le T(n) \le 6n - 3$.

4. Busca sequencial

Busca de um elemento $x$ em um vetor $A$. Retorna a posição de $x$, ou $-1$ se ele não estiver no vetor.

buscaSequencial(x, A, n)
1.  i = 0
2.  while i < n and A[i] ≠ x:
3.     i = i + 1
4.  if i >= n:
5.     return −1
6.  return i

Agora o laço é um while que pode parar cedo, assim que encontra $x$. Defina $n = |A|$, o número de elementos do vetor.

# op de cada linha

  • Linha 1, i = 0: 1 (atribuição).
  • Linha 2, i < n and A[i] ≠ x: 4 (comparação <, indexação A[i], comparação ≠, operador and).
  • Linha 3, i = i + 1: 2 (soma + atribuição).
  • Linhas 4, 5 e 6: 1 cada (comparação, retorno, retorno).

Melhor caso: $x$ está na primeira posição ($A[0] = x$)

E se x estiver na última posição?

Parece o pior caso, mas não é. Com $x = A[n-1]$, o corpo roda $n - 1$ vezes e a função retorna pela linha 6. Pela mesma convenção, $T(n) = 1 + 4(n-1) + 2(n-1) + 1 + 1 = 6n - 3$, menor que $6n + 3$. Quando $x$ não existe, o algoritmo percorre o vetor inteiro e ainda faz um último teste que falha por $i = n$. Esse é o máximo de passos. Confira na animação.

5. O cabeçalho de laço que para cedo

Reunindo as tabelas do professor, a regra que reproduz todas elas é:

Convenção do professor: # exec do cabeçalho

# exec do cabeçalho = número de vezes que o corpo executa. O teste final, que falha e encerra o laço, não é contado…

…exceto quando o corpo executa 0 vezes. Aí o único teste realizado conta 1. É o melhor caso da busca sequencial, com linha 2 = 1.

Na contagem rigorosa (Cormen), o teste de um laço roda sempre uma vez a mais que o corpo. No pior caso da busca, isso daria $4(n+1)$ na linha 2 e $T(n) = 6n + 7$. A diferença é só a constante, e o formato "$6n$ + constante" não muda. Na prova, siga o professor. Se quiser se proteger, escreva uma linha como "não conto o teste final do laço".

Detalhe: curto-circuito

Quando $i = n$, uma linguagem real nem avalia A[i] ≠ x, porque o and para no primeiro falso, e A[n] estaria fora do vetor. A tabela do professor conta as 4 op mesmo assim. Não perca tempo com isso na prova.

6. Caso médio (noção)

O slide define o caso médio como a média dos tempos de execução. Mais precisamente (Cormen, seção 2.2), é a média sobre todas as entradas de tamanho $n$, ponderada pela probabilidade de cada uma. Ele é frequentemente difícil de determinar, porque exige supor uma distribuição das entradas.

Exemplo (fora dos slides)

Na busca sequencial, se $x$ está no vetor e é igualmente provável em cada uma das $n$ posições, o corpo do laço roda em média $\frac{0 + 1 + \dots + (n-1)}{n} = \frac{n-1}{2}$ vezes. O custo médio fica em torno de $3n$: cerca da metade do pior caso, mas ainda proporcional a $n$.

O caso médio não é a média aritmética entre melhor e pior caso. Se as entradas de melhor caso forem raríssimas, a média fica muito perto do pior caso.

7. Método para "identifique o melhor e o pior caso"

  1. Ache as linhas variáveis: as que estão dentro de um if, os laços com condição sobre os dados (while … A[i] ≠ x), os return/quebra dentro de laços e os laços controlados por flag (repita … até !houveTroca).
  2. Para cada uma, pergunte: qual o mínimo e o máximo de vezes que ela pode rodar?
  3. Descreva a entrada que produz o mínimo (melhor caso) e a que produz o máximo (pior caso). Não diga "n pequeno". Diga como os valores estão arrumados.
  4. Monte uma tabela # op / # exec para cada caso e calcule $T(n)$. O professor faz duas tabelas separadas.
  5. Confira: $T_{\text{melhor}}(n) \le T_{\text{pior}}(n)$ para todo $n$.
