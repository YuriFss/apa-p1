1. Por que contar operações

Calcular o tempo exato de execução, em segundos, é inviável de modo geral, porque ele depende de:

  • hardware;
  • linguagem de programação;
  • custo exato de cada instrução;
  • etc.

Por isso a avaliação é feita em termos do número de operações básicas (ou etapas, ou passos) executadas, como função do tamanho da entrada $n$. Essa função se chama $T(n)$.

2. Operações básicas e # op de cada linha

Definição (slide 14)

Operações básicas são:

  • expressões de avaliação (comparações, somas, and, mod…);
  • atribuições de valores a variáveis;
  • indexação de um array (A[i]);
  • chamada de funções;
  • retorno de funções.

São fáceis de identificar no pseudocódigo. Supõe-se que cada uma leva uma quantidade constante de tempo. Isso é uma simplificação: na máquina real, uma multiplicação pode custar mais que uma soma, mas aqui todas valem 1.

Convenção do professor

O valor exato de # op de uma linha tem alguma folga. O próprio professor conta o for com 2 op no SomaVetor e com 1 op na soma de matrizes. O que ele cobra:

  1. uma contagem razoável e coerente (justifique em uma frase se tiver dúvida);
  2. a coluna # exec certa, que é a parte que muda a forma de $T(n)$.

Um for com 1 ou 2 op muda só os coeficientes de $T(n)$, não o formato. Errar # exec (por exemplo, escrever $n$ onde deveria ser $n^2$) muda a resposta inteira.

3. # exec: quantas vezes cada linha roda

A coluna # exec diz quantas vezes cada linha é executada, em função de $n$. Depois, multiplica-se linha a linha e soma-se tudo:

$$T(n) = \sum_{\text{linhas}} (\#\text{op}) \times (\#\text{exec}).$$

Regras para preencher # exec:

  • Fora de laços: a linha roda 1 vez.
  • Corpo de um laço: roda uma vez por iteração. for i = 0 to n − 1 tem $n$ iterações ($i = 0, 1, \dots, n-1$). for i = 1 to n − 1 tem $n - 1$.
  • Laço dentro de laço: multiplique. O corpo roda (iterações do laço de fora) × (iterações do laço de dentro), ou uma soma quando o laço de dentro depende do de fora (seção 6).
  • Cabeçalho do laço (a própria linha do for): veja a convenção abaixo.
Convenção do professor: cabeçalho do laço

O professor conta o cabeçalho do for com o mesmo # exec do corpo. Em for i = 0 to n − 1, a linha do for tem # exec = $n$.

Na execução real, o teste roda $n + 1$ vezes: o último teste ($i = n$) falha e encerra o laço. O Cormen conta esse teste extra ($n + 1$). O professor não conta. Na prova, siga a tabela do professor. A diferença é uma constante e não muda o formato de $T(n)$.

Na animação abaixo, esse último teste aparece em cinza, marcado como "não conta".

Linha por linha:

A novidade é o laço aninhado:

  1. Linha 1: criar a matriz é tratado como 1 op (uma chamada), 1 vez.
  2. Linha 2 (laço de fora): $i$ vai de 1 a $n$ → $n$ execuções. Aqui o professor contou o for com 1 op.
  3. Linha 3 (laço de dentro): para cada valor de $i$, o laço de $j$ roda $n$ vezes. São $n$ valores de $i$ × $n$ execuções = $n^2$.
  4. Linha 4 (corpo do laço de dentro): roda uma vez para cada par $(i, j)$ → $n^2$. São 8 op (6 indexações + soma + atribuição).
  5. $T(n) = 1\cdot 1 + 1\cdot n + 1\cdot n^2 + 8\cdot n^2 + 1\cdot 1 = 9n^2 + n + 2$.

$T(n) = 9n^2 + n + 2$

Cada quadrado = uma execução da linha 4

Linha $i$ da grade = uma iteração do laço de fora. Cada linha da grade tem $n$ quadrados (o laço de dentro). Total: $n \times n$.

E se o for valesse 2 op?

Ficaria $T(n) = 1 + 2n + 2n^2 + 8n^2 + 1 = 10n^2 + 2n + 2$. O formato é o mesmo, $an^2 + bn + c$. Por isso o professor tolera essa variação, mas não tolera um # exec errado.

6. Laços com limite dependente e a soma da PA

Na soma de matrizes, o laço de dentro roda sempre $n$ vezes. Muitos algoritmos (BubbleSort, InsertionSort, SelectionSort) têm um laço de dentro cujo tamanho depende do $i$ do laço de fora. Aí não dá para multiplicar: é preciso somar as iterações de cada volta.

SomaPrefixos(A, n)
1.  total = 0
2.  for i = 0 to n − 1:
3.     for j = 0 to i:
4.        total = total + A[j]
5.  return total

A pergunta é: quantas vezes a linha 4 roda, no total? Vamos responder em 6 passos curtos.

Passo 1: olhe só o laço de dentro, com $i$ congelado

Primeiro uma regra de contagem: for j = a to b roda $b - a + 1$ vezes, porque conta os valores $a, a+1, \dots, b$. Por exemplo, for j = 0 to 3 passa por $j = 0, 1, 2, 3$: são $3 - 0 + 1 = 4$ vezes.

No nosso laço de dentro, for j = 0 to i, o fim é $i$. Então ele roda $i - 0 + 1 = i + 1$ vezes. O número depende de quanto vale $i$ naquele momento:

se $i$ vale…$j$ passa por…linha 4 roda…
001 vez
10, 12 vezes
20, 1, 23 vezes
30, 1, 2, 34 vezes
$i$$0, 1, \dots, i$$i + 1$ vezes

Passo 2: desenrole o laço de fora

O laço de fora faz $i$ assumir $0, 1, 2, \dots, n-1$, um valor por volta. Em cada volta, o de dentro roda $i + 1$ vezes, conforme o passo 1. Para $n = 4$, escrevendo todas as execuções da linha 4, uma por par $(i, j)$:

volta i = 0:  (0,0)                         → 1 execução
volta i = 1:  (1,0) (1,1)                   → 2 execuções
volta i = 2:  (2,0) (2,1) (2,2)             → 3 execuções
volta i = 3:  (3,0) (3,1) (3,2) (3,3)       → 4 execuções
                                       total: 1 + 2 + 3 + 4 = 10

Cada volta tem uma execução a mais que a anterior, então o desenho forma um triângulo. Para um $n$ qualquer, a última volta é $i = n - 1$, com $(n-1) + 1 = n$ execuções. O total é:

$$\#\text{exec(linha 4)} = \underbrace{1}_{i=0} + \underbrace{2}_{i=1} + \underbrace{3}_{i=2} + \dots + \underbrace{n}_{i=n-1}.$$
Desenrolando o laço: cada quadrado é uma execução da linha 4 (o número dentro é o $j$)

Passo 3: por que não dá para multiplicar?

Na soma de matrizes, toda volta do laço de fora tinha o mesmo tamanho ($n$). Por isso o total era "voltas × tamanho de cada volta" $= n \times n$.

Aqui as voltas têm tamanhos diferentes (1, 2, 3, …, $n$). Não existe um único "tamanho da volta" para multiplicar. Mas dá para usar o tamanho médio:

  • são $n$ voltas;
  • os tamanhos sobem de 1 em 1, de $1$ até $n$, então a média é o ponto do meio: $\dfrac{1 + n}{2}$;
  • total = voltas × tamanho médio = $n \cdot \dfrac{n+1}{2}$.

Conferindo com $n = 4$: média $= \frac{1+4}{2} = 2{,}5$, e $4 \times 2{,}5 = 10$ ✓. É exatamente o 10 do passo 2.

Por que a média é (primeiro + último)/2?

Porque os tamanhos sobem sempre do mesmo tanto (de 1 em 1). Então eles se equilibram em volta do meio: 1 e 4 dão média 2,5, e 2 e 3 também dão média 2,5. Isso só funciona quando o aumento é constante (uma PA). Se o laço de dentro dobrasse de tamanho a cada volta, por exemplo, a conta seria outra.

Passo 4: por que $1 + 2 + \dots + n = \dfrac{n(n+1)}{2}$

(a) Com números (Gauss, $n = 10$). Junte o primeiro com o último, o segundo com o penúltimo, e assim por diante:

$$\underbrace{(1+10)}_{11} + \underbrace{(2+9)}_{11} + \underbrace{(3+8)}_{11} + \underbrace{(4+7)}_{11} + \underbrace{(5+6)}_{11} = 5 \times 11 = 55 = \frac{10 \cdot 11}{2}.$$

Todo par soma $n + 1 = 11$, e há $n/2 = 5$ pares.

(b) Com desenho. Pegue o triângulo de execuções, em azul, faça uma cópia, gire e encaixe ao lado, em laranja. As duas escadas formam um retângulo de $n$ linhas por $n + 1$ colunas:

Duas escadas iguais = um retângulo n × (n+1)

(c) Com álgebra (o mesmo truque do item a, escrito em geral). Escreva a soma duas vezes, uma de trás para frente, e some coluna a coluna:

$$\begin{aligned} S &= 1 + 2 + \dots + (n-1) + n\\ S &= n + (n-1) + \dots + 2 + 1\\ \hline 2S &= \underbrace{(n+1) + (n+1) + \dots + (n+1)}_{n \text{ parcelas}} = n(n+1) \end{aligned} \quad\Longrightarrow\quad S = \frac{n(n+1)}{2}.$$

Passo 5: o mesmo com a notação $\Sigma$

No gabarito, o professor escreve a soma com $\Sigma$. Leia $\displaystyle\sum_{i=0}^{n-1} (i+1)$ como: "para $i$ indo de $0$ até $n-1$, some o valor $i + 1$". Cada parcela é o número de execuções do laço de dentro naquela volta:

$$\sum_{i=0}^{n-1} (i+1) = \underbrace{(0+1)}_{i=0} + \underbrace{(1+1)}_{i=1} + \dots + \underbrace{((n-1)+1)}_{i=n-1} = 1 + 2 + \dots + n = \frac{n(n+1)}{2}.$$

Receita geral: # exec do corpo de dentro = $\sum$ (iterações do laço de dentro para cada valor de $i$). Quando as iterações são constantes, a soma vira uma multiplicação, como no caso $n \times n$ das matrizes.

Passo 6: e as outras linhas?

  • Linha 2 (laço de fora): $n$ voltas → # exec $= n$.
  • Linha 3 (cabeçalho do laço de dentro): pela convenção do professor, mesmo # exec do seu corpo → $\frac{n(n+1)}{2}$.
  • Linha 4 (corpo de dentro): $\frac{n(n+1)}{2}$, como acabamos de ver.

Atalho para a prova

Fórmula de bolso

Quando o laço de dentro aumenta ou diminui de 1 em 1 a cada volta do de fora:

$$\#\text{exec(corpo de dentro)} = V \times \frac{p + u}{2}$$
  • $V$ = quantas voltas o laço de fora dá;
  • $p$ = quantas vezes o laço de dentro roda na primeira volta;
  • $u$ = quantas vezes ele roda na última volta.

Com o laço de fora for i = 0 to n − 1 ($n$ voltas):

Laço de dentroiterações para cada $i$$p$ (volta $i=0$)$u$ (volta $i=n-1$)total

Repare: subir de $1$ até $n$ e descer de $n$ até $1$ dão o mesmo total, porque a soma é a mesma, só em outra ordem. Usar $\frac{n(n+1)}{2}$ ou $\frac{n(n-1)}{2}$ depende de o laço chegar até $n$ ou parar em $n-1$ (uma volta com 0 iterações).

Teste rápido: tente antes de abrir

Laço de fora for i = 1 to n − 1; laço de dentro for j = 0 to i − 1. Quantas vezes roda o corpo de dentro?

Resposta: o laço de fora dá $n - 1$ voltas. Na 1ª ($i = 1$), $j$ vai de 0 a 0: 1 iteração. Na última ($i = n-1$), $j$ vai de 0 a $n-2$: $n - 1$ iterações. Total $= (n-1) \cdot \frac{1 + (n-1)}{2} = \frac{n(n-1)}{2}$. Esse é o formato do laço do InsertionSort no pior caso.

Fechando a conta:

$$\begin{aligned} T(n) &= 1\cdot 1 + 2\cdot n + 2\cdot\tfrac{n(n+1)}{2} + 3\cdot\tfrac{n(n+1)}{2} + 1\cdot 1\\ &= 2 + 2n + 5\cdot\tfrac{n^2+n}{2} = 2 + 2n + \tfrac{5n^2}{2} + \tfrac{5n}{2}\\ &= \frac{5n^2 + 9n + 4}{2}. \end{aligned}$$

Confira com n = 2, que é sempre uma boa prática: $\frac{20 + 18 + 4}{2} = 21$. Na mão: linha 1 (1) + linha 2 roda 2× (4) + linhas 3 e 4 rodam 1 + 2 = 3× (3·2 + 3·3 = 15) + return (1) = 21 ✓.

7. Receita para a prova

  1. Defina $n$ (ex.: "$n$ = número de elementos de $A$").
  2. Coluna # op: para cada linha, desmonte e conte as operações básicas.
  3. Coluna # exec: fora de laço = 1; corpo de laço = nº de iterações; laço aninhado = produto ou somatório. Cabeçalho = mesmo # exec do corpo (convenção do professor).
  4. Monte $T(n) = \sum$ op × exec, escrevendo a soma por extenso antes de simplificar (o professor mostra essa linha no gabarito).
  5. Simplifique e confira com um $n$ pequeno ($n = 1$ ou $2$), simulando na mão.

Se o algoritmo tem if ou saída antecipada (return dentro do laço, while com condição sobre os dados), # exec depende de como os dados estão organizados. Esse é o assunto da próxima lição: melhor e pior caso.
