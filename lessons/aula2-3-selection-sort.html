1. Ideia

  • Ordena o vetor da esquerda para a direita.
  • A cada iteração, o menor elemento da parte não ordenada (à direita) é movido para sua posição final.

Na iteração $i$, as posições $0..i-1$ já têm os $i$ menores elementos, em ordem. O algoritmo procura o mínimo de $A[i..n-1]$ e troca esse mínimo com $A[i]$.

Insertion × Selection, a diferença central
  • Insertion: pega o próximo elemento e procura o lugar dele na parte ordenada. A busca para cedo se o lugar estiver perto.
  • Selection: fixa o lugar $i$ e procura o elemento que vai ali, o mínimo do resto. Para ter certeza de que é o mínimo, precisa olhar todo o resto, sempre.

2. Pseudocódigo, linha a linha

SelectionSort(A, n)
1. for i ← 0 to n − 2:
2.    i_min ← i
3.    for j ← i+1 to n − 1:
4.       if A[j] < A[i_min]:
5.          i_min ← j
6.    if A[i] ≠ A[i_min]:
7.       temp ← A[i]
8.       A[i] ← A[i_min]
9.       A[i_min] ← temp
10.return A
LinhaO que faz
1Posição $i$ que vai receber o próximo menor. Vai até $n-2$: quando sobra um elemento só, ele já está no lugar.
2Chute inicial: o mínimo é o próprio $A[i]$.
3–5Percorre o resto, $A[i+1..n-1]$. Se achar alguém menor que o mínimo atual, atualiza i_min.
6Só troca se o mínimo não for o próprio $A[i]$.
7–9Troca $A[i]$ com $A[i_{min}]$ usando uma variável temporária.

5. Melhor caso

O que depende dos dados?

  • Os laços das linhas 1 e 3 são independentes do conteúdo do array. O número de execuções depende só de $n$ (slide 39).
  • O número de execuções da linha 5 varia de acordo com a distribuição dos elementos, assim como as linhas 7–9. Mas a diferença é somente por um fator constante (slide 40).

O que significa "somente por um fator constante"? A linha 5 roda no máximo uma vez para cada execução da linha 4. Então ela pode mudar o coeficiente do $n^2$, mas não o formato: o algoritmo é quadrático em qualquer caso. Isso é bem diferente do InsertionSort, em que o melhor caso cai para linear.

Quantas vezes rodam os laços?

Linha 1: for i ← 0 to n − 2 tem $(n-2) - 0 + 1 = n - 1$ iterações.

Linhas 3 e 4: para cada $i$, o laço for j ← i+1 to n − 1 roda $(n-1) - (i+1) + 1 = n - 1 - i$ vezes:

valor de $i$012…$n-2$
iterações de $j$$n-1$$n-2$$n-3$…1

Pela fórmula de bolso: $V = n - 1$ voltas, primeira $p = n - 1$, última $u = 1$:

$$\#\text{exec(linhas 3, 4)} = (n-1)\cdot\frac{(n-1) + 1}{2} = \frac{(n-1)\,n}{2} = \frac{n^2 - n}{2}.$$

O slide escreve (n−1)(n−1+1)/2, que é a mesma coisa.

A entrada do melhor caso: vetor já ordenado

Com $A$ ordenado, o mínimo de $A[i..n-1]$ é sempre o próprio $A[i]$. O teste da linha 4 nunca é verdadeiro, então a linha 5 tem # exec $= 0$. O teste da linha 6 dá sempre falso, então as linhas 7–9 têm # exec $= 0$.

Juntando por # exec igual:

  • linhas 1, 2 e 6 ($n-1$ vezes): $2 + 1 + 3 = 6$;
  • linhas 3 e 4 ($\frac{n^2-n}{2}$ vezes): $3 + 3 = 6$;
  • linha 10: $1$.
$$\begin{aligned} T_m(n) &= 6(n-1) + \frac{6(n^2-n)}{2} + 1\\ &= 6n - 6 + 3n^2 - 3n + 1\\ &= 3n^2 + 6n - 3n - 5 \end{aligned}$$

Melhor caso: $T_m(n) = 3n^2 + 3n - 5$

Confira com $n = 2$, entrada $[1, 2]$: linha 1 (2) + linha 2 (1) + uma iteração com linhas 3 e 4 (6) + linha 6 (3) + return (1) = 13. Pela fórmula, $12 + 6 - 5 = 13$ ✓.

6. Selection × Insertion

Melhor caso do Selection × melhor e pior caso do Insertion

O melhor caso do SelectionSort (laranja) é uma parábola, como o pior do InsertionSort (vermelho). Só o melhor caso do InsertionSort (azul) é uma reta.

A última linha explica por que o SelectionSort ainda tem seu uso: quando escrever na memória é caro (memória flash, por exemplo), fazer no máximo $n-1$ trocas é uma vantagem.
