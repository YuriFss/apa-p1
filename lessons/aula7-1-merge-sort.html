MergeSort

1. Ideia e a função mergeSort

Problema: ordenar um vetor. Ideia básica: usar divisão e conquista. Dividir o vetor ao meio até o caso base (1 elemento, que já está ordenado) e depois mesclar (intercalar) as soluções dos subproblemas menores até chegar ao original.

mergeSort(A, p, r)
1. if p < r:
2.    q = floor((p+r)/2)
3.    mergeSort(A, p, q)
4.    mergeSort(A, q+1, r)
5.    merge(A, p, q, r)
  • Linha 1: se $p \ge r$, o trecho tem 0 ou 1 elemento e já está ordenado. É o caso base, e a função não faz nada.
  • Linha 2 (divisão): $q$ é o meio.
  • Linhas 3–4 (conquista): ordena $A[p..q]$ e $A[q+1..r]$ recursivamente.
  • Linha 5 (combinação): intercala as duas metades ordenadas em uma só.

3. A função merge

merge(A, p, q, r)
1.  L ← A[p .. q]
2.  R ← A[q+1 .. r]
3.  L.push_back(INF)
4.  R.push_back(INF)
5.  i ← j ← 1
6.  for k ← p to r:
7.     if L[i] <= R[j]:
8.        A[k] ← L[i]
9.        i ← i + 1
10.    else:
11.       A[k] ← R[j]
12.       j ← j + 1
  • Linhas 1–2: copia as duas metades, que já estão ordenadas, para os vetores auxiliares $L$ e $R$ (indexados a partir de 1).
  • Linhas 3–4: sentinela. Coloca $\infty$ no fim de cada um. Quando uma metade "acaba", o $\infty$ dela nunca ganha a comparação, e o algoritmo pega automaticamente da outra. Sem sentinela, seria preciso testar "acabou $L$?" a cada passo.
  • Linhas 6–12: para cada posição $k$ de $A[p..r]$, compara os menores restantes de cada lado, $L[i]$ e $R[j]$, coloca o menor em $A[k]$ e avança o índice daquele lado.
Quanto custa o merge

O for roda exatamente $r - p + 1$ vezes, uma por elemento do trecho, e cada iteração faz trabalho constante. A cópia das linhas 1–2 também é proporcional ao tamanho. Logo, o merge de um trecho com $n$ elementos custa $\Theta(n)$. É o $f(n)$ da recorrência.

Num dos slides, a linha 7 aparece como L[i] < R[j]. Os dois funcionam. Com <=, em caso de empate pega-se primeiro da esquerda, o que mantém a ordem original dos iguais: o algoritmo fica estável.

4. Animação completa

mergeSort + merge, passo a passo

Em A, só o trecho $[p..r]$ da chamada atual fica aceso. Em $L$ e $R$, os índices $i$ e $j$ apontam o menor restante de cada lado. Use "auto" ou "fim": são muitos passos.

5. Melhor e pior caso?

Slide 8

Não existe nem melhor nem pior caso! O MergeSort sempre divide o vetor o mesmo número de vezes, independentemente da organização dos elementos. E o merge sempre percorre todos os $r - p + 1$ elementos. Ordenado, invertido ou aleatório: o custo é o mesmo.

Compare com o InsertionSort, que vai de $\Theta(n)$ (ordenado) a $\Theta(n^2)$ (invertido). O MergeSort é $\Theta(n\log n)$ para qualquer entrada.

6. A recorrência

Para qualquer valor de $n$, as metades têm tamanhos $\lceil n/2 \rceil$ e $\lfloor n/2 \rfloor$:

$$T(n) = \begin{cases} 1 & n = 1 \\ T\!\left(\left\lceil \frac{n}{2}\right\rceil\right) + T\!\left(\left\lfloor \frac{n}{2}\right\rfloor\right) + c\,n & n > 1\end{cases}$$

Quando $n$ é potência de 2, as metades são iguais:

  • $a = 2$: duas chamadas recursivas (linhas 3 e 4);
  • $b = 2$: cada uma com metade do tamanho;
  • $f(n) = n$: o merge (com $c = 1$).
$$T(n) = \begin{cases} 1 & n = 1 \\ 2\,T\!\left(\dfrac{n}{2}\right) + n & n > 1\end{cases}$$

7. Resolvendo: $\Theta(n\log n)$

Complemento: os slides param na recorrência. Aqui vão dois jeitos de resolver.

Pela árvore de recursão

Custo por nível de $T(n) = 2T(n/2) + n$
  • No nível $i$ há $2^i$ nós, cada um com um subproblema de tamanho $n/2^i$ e custo próprio $n/2^i$.
  • Custo do nível $i$: $2^i \cdot \frac{n}{2^i} = n$. Todo nível custa $n$.
  • Os níveis vão de $i = 0$ até o tamanho chegar a 1: $n/2^i = 1 \iff i = \log_2 n$. São $\log_2 n + 1$ níveis.
$$T(n) = n \cdot (\log_2 n + 1) = n\log_2 n + n = \Theta(n \log n).$$

Pelo método iterativo

$$\begin{aligned} T(n) &= 2\,T(n/2) + n && \text{passo 1}\\ &= 2\big(2\,T(n/4) + n/2\big) + n = 4\,T(n/4) + 2n && \text{passo 2}\\ &= 4\big(2\,T(n/8) + n/4\big) + 2n = 8\,T(n/8) + 3n && \text{passo 3}\\ &= 2^k\,T(n/2^k) + k\,n && \text{passo } k \end{aligned}$$

Caso base: $n/2^k = 1 \iff k = \log_2 n$. Então $2^k = n$ e:

$$T(n) = n\,T(1) + n\log_2 n = n\log_2 n + n.$$

$T(n) = n\log_2 n + n = \Theta(n\log n)$

Confira: $T(2) = 2T(1) + 2 = 4$ e a fórmula dá $2\cdot1 + 2 = 4$ ✓. $T(4) = 2\cdot4 + 4 = 12$ e a fórmula dá $4\cdot2 + 4 = 12$ ✓. $T(8) = 2\cdot12 + 8 = 32$ e a fórmula dá $8\cdot3 + 8 = 32$ ✓.

Atalho (Teorema Mestre, só para conferir)

Para $T(n) = aT(n/b) + f(n)$, compare $f(n)$ com $n^{\log_b a}$. No MergeSort, $n^{\log_2 2} = n$, que é igual a $f(n) = n$. Quando empatam, a resposta é $\Theta(n^{\log_b a}\log n) = \Theta(n\log n)$. Na busca binária, $n^{\log_2 1} = n^0 = 1 = f(n)$, e o empate dá $\Theta(\log n)$. O professor citou o método mestre, mas a disciplina foca no iterativo.
