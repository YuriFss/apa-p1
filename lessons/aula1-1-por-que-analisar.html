1. Funcionar não basta

Um algoritmo é uma sequência finita de passos bem definidos que resolve um problema. Uma receita, o caminho de casa até a universidade e o jeito de atravessar a rua são algoritmos do dia a dia.

No início da programação, o critério costuma ser só um: "se resolve o problema, ok". O professor insiste que isso geralmente não é suficiente. Dois algoritmos corretos para o mesmo problema podem gastar quantidades de recursos muito diferentes:

  • tempo de processamento, o foco desta disciplina;
  • memória;
  • consumo de dados (internet), energia etc.

Em APA, queremos responder três perguntas:

  1. O algoritmo desenvolvido é eficiente?
  2. Existe uma alternativa melhor?
  3. O algoritmo usado é o melhor para o meu cenário?

Para isso, a disciplina analisa a corretude e o desempenho de algoritmos, ensina técnicas de projeto mais sofisticadas (divisão e conquista, por exemplo) e estuda a complexidade de problemas.

2. Exemplo: duas versões de Fibonacci

A sequência de Fibonacci é $F_0 = 0$, $F_1 = 1$ e $F_n = F_{n-1} + F_{n-2}$ para $n \ge 2$, ou seja, 0, 1, 1, 2, 3, 5, 8, 13, … O professor mostra duas implementações corretas.

fibonacci1(n)
1. if n = 0: return 0
2. if n = 1: return 1

3. return fibonacci1(n−1) + fibonacci1(n−2)
fibonacci2(n)
1. if n = 0: return 0
2. crie um vetor f[0...n]
3. f[0] = 0, f[1] = 1

4. for i = 2...n:
5.    f[i] = f[i−1] + f[i−2]

6. return f[n]

O que fibonacci1 faz de fato

Cada chamada com $n \ge 2$ faz duas chamadas novas. A árvore abaixo mostra todas as chamadas feitas para calcular fibonacci1(n). Os nós em laranja calculam um valor que já foi calculado antes em outro ramo. Todo esse trabalho é repetido.

Árvore de chamadas de fibonacci1(n)

Contando as chamadas: seja $C(n)$ o número de chamadas feitas por fibonacci1(n). A própria chamada conta 1, mais as chamadas dos dois filhos:

$$C(0) = C(1) = 1, \qquad C(n) = C(n-1) + C(n-2) + 1 \quad (n \ge 2).$$

A conta segue o mesmo padrão do próprio Fibonacci e dá $C(n) = 2F_{n+1} - 1$. Confira na árvore: $C(5) = 2 \cdot F_6 - 1 = 2 \cdot 8 - 1 = 15$. Como $F_n$ cresce aproximadamente como $1{,}618^n$, o número de chamadas cresce exponencialmente em $n$.

Já fibonacci2 preenche o vetor uma posição por vez. O laço da linha 4 roda $n - 1$ vezes, então o trabalho cresce linearmente em $n$.

Trabalho de cada versão conforme n cresce

Laranja: chamadas recursivas de fibonacci1, $2F_{n+1} - 1$. Azul: iterações do laço de fibonacci2, $n - 1$. Com n = 20 a linha azul já parece colada no zero. Ative a escala log para ver as duas formas: reta inclinada (exponencial) contra curva achatada (linear).

Para ter noção

fibonacci1(200) faria $2F_{201} - 1 \approx 9{,}1 \times 10^{41}$ chamadas. A 1 bilhão de chamadas por segundo, isso levaria cerca de $2{,}9 \times 10^{25}$ anos, mais de $10^{15}$ vezes a idade do universo. fibonacci2(200) faz 199 iterações.

Os slides fecham com: "Como veremos nas próximas aulas, essa segunda implementação é, no geral, muito mais eficiente. É a melhor?"

Fora dos slides (Dasgupta, cap. 0)

Não. fibonacci2 guarda o vetor inteiro, mas só precisa dos dois últimos valores. Com duas variáveis, o tempo continua linear e a memória fica constante. Também existe um método por potência de matriz que usa cerca de $\log_2 n$ multiplicações. A pergunta do professor serve para lembrar que, depois de achar uma versão eficiente, ainda vale perguntar se existe uma alternativa melhor.

3. Objetivo da análise de complexidade

Definição (slide 5)

O objetivo da análise de complexidade é possibilitar medir a eficiência de algoritmos.

Analisar um algoritmo é prever as exigências de recursos computacionais:

  • tempo de execução → complexidade temporal;
  • memória → complexidade espacial.

Nesta disciplina, "complexidade" sem adjetivo quase sempre quer dizer complexidade temporal.

4. Duas abordagens: experimental e teórica

Há dois jeitos de saber quanto tempo um algoritmo gasta.

Análise experimental

  1. Implementar o algoritmo.
  2. Executar o programa variando a entrada (tamanhos e conteúdos diferentes).
  3. Medir o tempo de execução com algum método (cronômetro do sistema, por exemplo).
  4. Imprimir os resultados, geralmente em um gráfico de tempo × tamanho da entrada.

Os slides apontam três problemas:

  • É necessário implementar o algoritmo, o que pode ser difícil e exige esforço.
  • Os resultados podem ser tendenciosos: talvez as entradas em que o algoritmo seria menos (ou mais) eficiente não tenham sido testadas.
  • A comparação entre dois algoritmos precisa usar o mesmo ambiente (hardware + software). Um tempo medido no seu notebook não vale para o meu.

Análise teórica

  • Não é necessário implementar: a análise é feita sobre uma descrição de alto nível, como o pseudocódigo.
  • Leva em consideração todas as entradas possíveis, não só as que alguém escolheu testar.
  • Não depende do ambiente computacional (hardware ou software).
  • Caracteriza a eficiência como uma função do tamanho da entrada.
  • É uma aproximação da complexidade, não o tempo exato em segundos.

O resto da disciplina usa a abordagem teórica.

5. Tamanho da entrada, $n$

A análise teórica expressa o custo em função do tamanho da entrada. O que conta como "tamanho" depende do problema:

  • Ordenação: o número de elementos do vetor.
  • Busca em grafo: o número de vértices e arestas do grafo.

Para simplificar, usamos a letra $n$. A definição precisa de $n$ é dada em cada problema. Às vezes há dois parâmetros, como na questão 8 da lista, onde o custo é $T(n, m)$ com $n$ = tamanho do texto e $m$ = tamanho do padrão.

Atenção na prova

Ao começar uma análise, diga o que é $n$. Na busca sequencial o professor escreve: "vamos definir $n$ como sendo $n = |A|$", ou seja, o número de elementos do vetor $A$.
